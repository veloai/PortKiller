# PortKiller Pet — 이 프로그램이 무엇을 읽고 무엇을 읽지 않는가

사내 배포 전 보안 검토에 함께 제출하는 문서다.

> **2026-09-30 변경 — 개인용 전환.** 이 프로그램은 이제 배포용이 아니라 **본인 한 사람이 자기 PC에서 쓰는 개인용**이다.
> 그에 맞춰 "Genian NAC 자동 로그인" 기능이 들어갔고, 그래서 아래 표의 "창 제목·프로그램 이름은 안 읽음"은
> **이 기능을 켰을 때에 한해 예외**가 생겼다. 자세한 것은 "NAC 자동 로그인" 절.
> 이 절 이전의 "사내 배포" 전제 문장들은 배포할 때를 위한 기준으로 남겨 둔다.
"안 한다"는 말이 아니라 **코드에서 그 기능을 쓸 수 없게 만들어 둔 것**이 요점이다.

## 한 줄 요약

바탕화면에 캐릭터를 띄우고, 사용자가 원할 때 AI 에게 한 번 물어봐 주는 프로그램이다.
입력 내용을 읽지 않으며, 기록은 본인 PC에만 남는다.

**나가는 통신은 한 가지뿐이다** — 사용자가 물어보기 창에 직접 적고 엔터를 누른 그 순간,
사용자가 직접 등록한 AI 서비스로 그 문장만 보낸다. 그 밖에는 나가는 통신이 없다.

## 읽는 것 / 읽지 않는 것

| | 내용 | 근거 |
|---|---|---|
| 읽음 | 마지막 입력 이후 지난 시간 (숫자 하나) | `ActivityMonitor.cs` — `GetLastInputInfo` |
| **안 읽음** | 어떤 키를 눌렀는지 | 키 상태를 읽는 함수를 호출하지 않는다 |
| **안 읽음** | 마우스 커서 위치 | 커서 좌표를 읽는 함수를 호출하지 않는다. **예외: 브리핑 카드 위에 있을 때만**, 내 창의 마우스 이벤트(`MouseMove`)로 카드 안의 좌표를 받는다 (아래 절) |
| **안 읽음** | 어디를 클릭했는지, 무엇을 클릭했는지 | 클릭 대상을 조회하지 않는다 |
| **안 읽음** | 창 제목, 실행 중인 프로그램 이름 | **NAC 자동 로그인을 켠 경우만 예외** (아래 절) — 꺼져 있으면 호출하지 않는다 |
| **안 읽음** | 화면 내용, 파일 내용, 클립보드 | 해당 API를 호출하지 않는다 |

## 쓰지 않기로 한 기술

의도적으로 배제했다. 기능이 아쉬워도 넣지 않는다.

- **전역 키보드/마우스 훅 (`SetWindowsHookEx`)** — 입력을 가로채는 방식.
  백신·EDR이 키로거로 판정하는 대표 패턴이라 처음부터 설계에서 뺐다.
- **실행 중 코드 컴파일** — `csc.exe` 등으로 런타임에 코드를 만들어 실행하는 방식.
  정적 검사를 우회하는 기법으로 분류되므로 쓰지 않는다.
- **자기 자신을 교체하는 자동 업데이트** — 새 실행 파일을 받아 배치 파일로 덮어쓰는 방식.
  악성코드의 전형적 동작이라 쓰지 않는다. 새 버전은 정식 배포 경로로만 내려간다.
- **관리자 권한 요구** — `app.manifest`에서 `asInvoker`로 고정.

## 네트워크 (2026-09-15 변경 — AI 물어보기 기능 추가)

> 이 항목은 예전에 "통신 코드가 없다"였다. AI 기능이 들어가면서 사실이 바뀌었으므로
> 같은 변경에서 다시 썼다. 검토는 이 절을 기준으로 한다.

### 언제 나가나

**사용자가 물어보기 창에 글을 적고 엔터를 누를 때만.** 그 외에는 나가지 않는다.
주기적 확인, 업데이트 확인, 사용 통계, 오류 보고 — 전부 없다.
열쇠를 등록하지 않으면 요청이 만들어지지도 않는다(보내기 전에 막는다).

### 어디로 나가나

사용자가 고른 한 곳으로만 간다. 주소는 코드에 **상수로 박혀 있고 설정으로 바꿀 수 없다.**

| 고른 곳 | 주소 | 코드 |
|---|---|---|
| Gemini | `https://generativelanguage.googleapis.com` | `GeminiChatClient.cs` |
| OpenAI | `https://api.openai.com` | `OpenAiChatClient.cs` |

주소를 환경변수나 설정 파일로 바꾸는 길을 **일부러 만들지 않았다.** 검사 편의로 그 길을
열면 배포본에 "아무 서버로나 보낼 수 있는 구멍"이 남는다. 검사는 대신 통신을 아예 하지 않는
가짜 객체를 끼워 넣는 방식(`--stub-ai`)으로 한다.

### 무엇이 나가나

- 사용자가 **그 칸에 직접 타이핑한 문장**
- 말투 지시문 (설정 창에서 사용자가 보고 고칠 수 있는 문장)
- 모델 이름
- 열쇠 (해당 서비스의 인증 머리글)

**나가지 않는 것**: 화면 내용, 다른 창 제목, 클립보드, 파일, 키 입력, 수첩 내용,
펫 상태, PC 이름, 사용자 이름, 그 어떤 식별자도.
보내는 본문은 위 네 가지가 전부이며, `AiClientTests` 가 보낸 본문을 다시 읽어 확인한다.

### 무엇이 남나

**질문도 답도 저장하지 않는다.** 창을 닫으면 사라진다. 대화 이력 파일이 없다.

## 브리핑 (상태 보기)

레서판다가 안경을 쓰고 서서, 옆에 세운 상태 카드를 지시봉으로 짚으며 설명한다. 트레이 "상태 보기"나 펫 우클릭 메뉴에서 켠다.

- 지시봉이 향할 방향을 정하려고 마우스 위치가 필요하지만, **카드 위에서 일어나는 내 창의 마우스 이벤트**만 쓴다.
  카드 밖의 커서 위치, 다른 프로그램 위의 움직임은 받을 수 없다(이벤트가 오지 않는다).
  `GetCursorPos`·전역 훅 같은 외부 함수를 추가하지 않았다.
- 위치는 저장하지도 보내지도 않는다. 지시봉 각도와 항목 강조에만 쓰고 바로 버린다.
- 통신·저장 변화 없음.

## 개발 환경 상태 (2026-11 추가)

펫이 Docker·컨테이너·로컬 서버가 돌고 있는지 1분마다 보고, 멈추거나 되살아나면 알린다. 브리핑 카드에 "개발 환경" 칸으로 보인다.

- **보는 것**: `Docker Desktop` 프로세스가 있는지(이름만), `docker ps -a` 가 돌려주는 컨테이너 이름·상태,
  윈도우가 알려 주는 이 PC 의 TCP 대기 포트 목록. 포트에는 **접속하지 않는다.** 바깥으로 나가는 통신은 없다.
- **확인 목록**: `%APPDATA%\PortKillerPet\devstatus.json` (처음 켤 때 기본 목록으로 만들어진다. 고쳐서 항목을 바꿀 수 있다).
- 결과는 화면에만 쓰고 저장하지 않는다.

## MCP 서버 (2026-11 추가)

Claude Code·ALFA 같은 에이전트가 펫을 부를 수 있게, PKP 안에서 MCP(Model Context Protocol) 서버를 연다.

- **어디서 열리나**: `127.0.0.1:47420` (이 PC 안에서만. 다른 PC 에서는 닿지 않는다). 바깥으로 나가는 통신은 없다.
- **누가 부를 수 있나**: `%APPDATA%\PortKillerPet\mcp.key` 의 열쇠를 `Authorization: Bearer` 로 보낸 쪽만. 처음 켤 때 무작위로 만든다.
  브라우저가 붙이는 `Origin` 이 localhost 가 아니면 거절한다(웹페이지가 몰래 부르는 것 차단).
- **도구는 일부러 좁게**: `pet_say`(말풍선·표정), `pet_status`(펫 상태 읽기), `dev_status`(개발 환경 상태 읽기), `pet_briefing`(브리핑 켜고 끄기).
  파일 읽기·명령 실행·화면 보기·키보드/마우스 조작 도구는 **없다.**
- 검사: `scripts/mcp-smoke.ps1` (정상 호출과 막힘 4가지를 확인).

## NAC 자동 로그인 (2026-09-30 추가, 기본 꺼짐)

재부팅 뒤 뜨는 Genian NAC 로그인 창에 아이디·비밀번호를 대신 넣고 [인증]을 누른다.

- **켜야만 동작한다.** 트레이 "🔐 NAC 자동 로그인"에서 아이디·비밀번호를 저장하고 켜짐을 체크했을 때만.
  등록이 없거나 꺼져 있으면 창을 찾는 코드가 아예 돌지 않는다.
- **무엇을 읽나**: 켜져 있을 때, 최상위 창의 **소유 프로세스 이름**만 본다. 이름이 `Gn` 으로 시작하는
  Genian 에이전트(`GnAgent` 등)의 창만 대상이고, 다른 프로그램 창은 제목·내용을 읽지 않고 지나간다.
  대상 창 안에서는 입력 칸·[인증] 버튼의 종류와 이름을 본다. **입력된 값은 읽지 않는다**
  (비밀번호 칸은 윈도우가 읽기를 막는다. 아이디 칸만 들어갔는지 확인한다).
- **어떻게 넣나**: 윈도우 UI 자동화(`System.Windows.Automation`, .NET 기본 제공)의 값 설정·누르기.
  키 입력 흉내(`SendInput`)·창 메시지·전역 훅을 쓰지 않아서 **외부 함수 호출 목록은 그대로다.**
  관리자 권한 창에는 윈도우가 막아 닿지 못하며, 우회하려 하지 않는다.
- **얼마나 기다리나**: 펫이 켜진 뒤 2분. 그 안에 창이 안 뜨면(이미 인증됨) 조용히 끝난다.
  재부팅 때 쓰려면 "시작 시 자동 실행"을 사용자가 직접 켜야 한다(자동으로 켜지 않는다).
- **한 번만 시도한다.** 비밀번호가 틀려도 되풀이하지 않는다 — 계정 잠금 방지. 다시 하려면 사용자가
  설정 창의 "지금 시도"를 직접 누른다.
- **저장**: `%APPDATA%\PortKillerPet
ac.dat`, DPAPI(현재 사용자) 암호화. 세이브·AI 설정과 다른 파일.
  저장한 비밀번호를 화면에 다시 보여 주지 않고, 설정 창에서 지울 수 있다.
  실측: 가짜 값으로 ① 왕복 저장 ② 파일에서 평문 미검출 ③ 지우기 후 파일 삭제를 확인했다.
- **통신**: 없다. 네트워크 절의 "나가는 통신은 한 가지뿐"은 그대로다.
- **실행 확인**: 켤 때마다 Genian 에이전트(GnAgent)가 구동 중인지 프로세스 **이름**으로만 확인해 말풍선에 true/false 로 알리고,
  `%APPDATA%\PortKillerPet\genian-status.txt` 에 한 줄(시각·true/false·Gn 프로세스 이름·로그인 창 유무·설정 상태)을 덧붙인다.
  설정 창의 "Genian 확인"으로 언제든 다시 볼 수 있다. 입력하거나 읽어 가는 값은 없다.
- **글자를 넣는 법(2026-11 변경)**: Genian 입력 칸은 UI 자동화의 값 넣기를 지원하지 않아서(진단: `patterns=[]`),
  그 칸의 창 핸들에 `WM_SETTEXT` 메시지를 보내 글자를 지정한다(`SendMessageW`, `NacAutoLogin.cs`).
  키 입력 흉내가 아니며 특정 칸 하나에만 들어간다. 넣은 뒤 두 칸의 **글자 수만** 확인하고(`WM_GETTEXTLENGTH`, 내용은 읽지 않음),
  하나라도 맞지 않으면 [인증]을 누르지 않는다. 결과는 `nac-log.txt` 에 한 줄씩 남긴다(아이디·비밀번호는 쓰지 않음).
- **창을 알아보는 법**: Genian 로그인 창(클래스 `CN_GNAUTH_DLG`)은 입력 칸을 `Pane`(윈도우 클래스 `Edit`)으로 내보내고 비밀번호 표시가 없다.
  그래서 클래스가 `Edit` 인 칸을 입력 칸으로 보고, 칸 이름이 "비밀번호"인 것을 비밀번호 칸으로, 나머지를 아이디 칸으로 본다. [인증] 버튼은 이름 또는 고유 번호(1003)로 찾는다.
- **자동 진단 기록**: 로그인 창을 알아보지 못했거나 입력이 거부되면 창의 구조(종류·이름·번호·지원 방식)를 `nac-dump.txt` 에 스스로 남긴다. 입력값은 담지 않는다.
- **진단**: 설정 창의 "창 구조 저장"이 `nac-dump.txt` 를 만든다. 창의 구조(종류·이름·자동화 id)만 담고 입력값은 없다.

## AI 열쇠 보관

경로: `%APPDATA%\PortKillerPet\keys.dat`

- **윈도우 DPAPI 로 암호화**해서 둔다 (`ProtectedData`, 현재 사용자 범위).
  파일을 다른 PC나 다른 계정으로 옮기면 복호화되지 않는다 — 파일만 훔쳐도 쓸 수 없다.
- 세이브(`save.json`)와 **다른 파일**이다. 세이브를 백업하거나 남에게 보내도 열쇠는 안 따라간다.
- 화면 입력은 `PasswordBox` 로만 받는다. **등록된 열쇠를 화면에 다시 보여 주지 않는다.**
- 오류 메시지에 응답 본문을 붙이지 않는다. 일부 서비스가 401 응답에 보낸 열쇠를 되비쳐 주는데,
  그걸 화면에 띄우면 열쇠가 그대로 노출된다 (`AiClientTests` 가 이 경로를 막고 있다).
- 트레이 메뉴의 "AI 설정"에서 언제든 전부 지울 수 있다.

실측: `scripts/verify-ai-keys.ps1` — 가짜 열쇠를 등록한 뒤
① `keys.dat` 안에서 그 문자열이 **평문으로 발견되지 않음**
② `save.json`·`ai.json` 에도 없음
③ "전부 지우기"로 파일이 실제로 사라짐 — 셋을 확인한다.

## 외부 라이브러리

**NuGet 패키지를 하나도 쓰지 않는다.** AI 기능을 넣은 뒤에도 그대로다.

열쇠 암호화에 쓰는 `ProtectedData` 는 Windows 데스크톱 런타임에 기본 포함돼 있다.
직접 `CryptProtectData` 를 `DllImport` 할 필요도 없어서, 아래 "외부 함수 호출 목록"도
늘어나지 않았다.

> 처음에는 패키지가 필요한 줄 알고 `System.Security.Cryptography.ProtectedData` 를 넣었다.
> 시험 프로젝트가 데스크톱 런타임이 아니어서 생긴 오판이었다 — 배포본에 그 DLL 이 안 들어간
> 것을 보고 빼 보니 그대로 돌아갔다(`scripts/verify-ai-keys.ps1` 재실행으로 확인).

- `keys.dat` — AI 열쇠. **암호화됨** (위 "AI 열쇠 보관" 참고)
- `nac.dat` — NAC 아이디·비밀번호. **암호화됨** (위 "NAC 자동 로그인" 참고)
- `nac-dump.txt` — 진단을 눌렀을 때만 생기는 창 구조 기록(값 없음)

질문과 답은 저장하지 않는다.

폴더를 지우면 흔적이 남지 않는다. 레지스트리는 아래 한 곳만 쓴다.

## 시작 프로그램 등록

- 위치 두 곳: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 의 `PortKillerPet` 값과, 사용자 시작 폴더의 `PortKillerPet.lnk` 바로가기.
  레지스트리 항목만으로는 재부팅 때 안 뜨는 PC 가 있어서 윈도우의 다른 길(시작 폴더)을 같이 건다. 둘 다 현재 사용자 영역이다.
- **기본값은 꺼짐.** 사용자가 트레이 메뉴나 NAC 설정 창에서 직접 켤 때만 등록된다. 끄면 둘 다 지운다.
- 시스템 전역(HKLM)은 건드리지 않는다.
- 두 길이 겹쳐도 앱은 한 번만 뜬다(이름 있는 뮤텍스, 같은 계정 안에서만).
- `%APPDATA%\PortKillerPet\startup.log` 에 시작·종료·오류를 한 줄씩 남긴다(시각, 프로세스 번호, 실행 인자, 예외 종류·메시지). 개인 정보나 입력 내용은 담지 않고, 64KB 를 넘으면 앞부분을 잘라 낸다.

## 배포

- 서명된 실행 파일로만 배포한다.
- 메신저로 zip을 돌리는 방식은 쓰지 않는다. 사내 정식 배포 경로를 통한다.
- 빌드는 트리밍(`PublishTrimmed`)과 단일 파일 묶기를 사용하지 않는다.
  오탐의 주 원인이며, `Directory.Build.props`에서 전 프로젝트 공통으로 꺼두었다.

## 확인 방법

위 주장은 코드에서 직접 확인할 수 있다. 외부 함수 호출은 아래 세 곳이 전부다.

```
src/PortKiller.Platform/ActivityMonitor.cs   GetLastInputInfo
src/PortKiller.App/NativeMethods.cs          GetWindowLongPtrW, SetWindowLongPtrW
src/PortKiller.Platform/AutostartManager.cs  레지스트리 (Microsoft.Win32.Registry)
```

`src/` 아래에서 `DllImport`를 검색하면 이 목록이 전부인지 바로 확인된다.

> 위 주장은 **배포되는 앱 코드(`src/`) 기준**이다.
> `scripts/verify-clickthrough.ps1` 은 개발용 검사 도구라 커서를 옮기는 함수를 쓴다.
> 이 파일은 빌드에 포함되지 않으며 배포물에 들어가지 않는다.
창 함수 둘은 창을 Alt+Tab 목록에서 빼는 용도이며, 입력과 무관하다.
