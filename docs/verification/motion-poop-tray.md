# 움직임 · 응아 · 트레이 실측 기록

> 2026-09-14 / Windows 11 Pro 26200 / .NET 9.0.318 / 1920x1080, 배율 100%

검사 스크립트: `scripts/verify-motion.ps1`, `scripts/verify-tray.ps1`

## 움직임

화면을 찍어 펫 색을 찾는 방식으로 잰다.
단순히 "그 색 픽셀이 있나"로 세면 배경(IDE 문법 강조 초록 등)에 오염된다.
펫은 지름 96px 덩어리라 **가로로 길게 이어진 구간**이 나오므로, 그걸로 구분한다.

| | 결과 |
|---|---|
| t=3s 펫 위치 | x=920, 이어진 구간 80px |
| t=11s 펫 위치 | x=881, 이어진 구간 80px |
| 8초간 이동 | **39px** |
| 응아 | x=762 에 39px 덩어리 — 가려지지 않고 보임 |

**통과.** 펫이 실제로 걷고, 응아가 화면에 남는다.

규칙 자체(걷기·중력·드래그·화면 밖 이탈 금지)는 `PetMotionTests` 7개가 따로 막는다.

## 트레이 — **시각 확인 못 함**

정직하게 적는다. 트레이 아이콘은 **코드상 만들어지고 앱은 정상 동작하지만,
작업표시줄에서 눈으로 확인하지 못했다.**

| | 결과 |
|---|---|
| 앱 실행 유지 | 예 (트레이 생성 실패 시 여기서 죽는다) |
| 작업표시줄에서 아이콘 색 검출 | 실행 중 71px / 종료 후 71px — **차이 0** |
| 숨김 영역(`TopLevelWindowForOverflowXamlIsland`) | 존재하나 접혀 있음 |

윈도우 11은 새로 등록된 트레이 아이콘을 **기본적으로 숨김 영역에 넣는다.**
그래서 작업표시줄 띠를 찍어도 안 나온다. 검출된 71px 는 다른 프로그램 아이콘이다.

**사람이 한 번 확인해야 한다.** 시계 왼쪽 `∧` 를 눌러 파란 원 아이콘이 있는지 보면 된다.
이건 자동으로 증명하려면 숨김 영역을 클릭해서 펼쳐야 하는데,
그만한 값어치가 없다고 판단해 사람 확인으로 남긴다.

## 이 측정으로 잡은 버그

**청결도가 15초 만에 0이 됐다.**

응아가 바닥에 있으면 더러워지는 양을 **호출 횟수에 비례**해 깎고 있었다.
화면이 초당 60번 도니까, 응아 2개에 초당 14.4씩 깎여 7초면 0이 된다.
시간에 비례하도록 고쳤다 (응아 1개당 시간당 12).

테스트가 이걸 못 잡았던 이유: 시험이 전부 큰 시간 단위로 한 번씩만 흘려보냈다.
같은 1시간을 **한 번에 흘린 경우와 3600번 나눠 흘린 경우의 결과가 같아야 한다**는
시험(`DirtinessDependsOnElapsedTimeNotTickCount`)을 추가해 재발을 막았다.

고친 뒤 15초 실행: 청결 100 유지.
