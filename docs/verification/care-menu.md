# 돌보기 메뉴 · 말풍선 실측 기록

> 2026-09-14 / Windows 11 Pro 26200 / .NET 9.0.318 / 1920x1080, 배율 100%

검사 스크립트: `scripts/verify-care.ps1`

## 무엇을 쟀나

말로 "메뉴가 열린다"고 하지 않고, **우클릭부터 항목 선택까지 실제로 눌러서** 확인했다.

| 단계 | 확인 방법 | 결과 |
|---|---|---|
| 시작 인사 말풍선 | 펫 위쪽 띠에서 흰 상자 검출 | 184px 흰 구간 — 보임 |
| 우클릭으로 메뉴 열기 | 앱 소유의 작은 창이 새로 생기는지 | 0개 → 1개 (159x148) |
| 항목 선택 | 메뉴 위치를 읽어 첫 항목 클릭 | "우와 배부르다!" 말풍선 |

**통과.**

## 함정 하나

처음에는 커서 아래쪽을 눌렀다가 실패했다.
**메뉴가 커서 위쪽에 열렸기 때문**이다 — 펫이 화면 맨 아래에 서 있어서 아래에 자리가 없었다.

검사 스크립트가 좌표를 추측하지 않고 **메뉴 창의 실제 위치를 읽어서** 누르도록 고쳤다.
제품 쪽 문제가 아니라 검사 방식의 문제였다.

## 할 수 없는 항목은 회색으로

메뉴를 열 때마다 지금 할 수 있는 것만 켠다. 눌러 봐야 거절당하는 항목을 켜 두면 헛수고를 시킨다.

| 항목 | 켜지는 조건 |
|---|---|
| 약 | 아플 때만 |
| 놀기 | 아프지 않을 때만 |
| 청소 | 치울 응아가 있을 때만 |
| 재우기 | 자고 있지 않을 때만 |
| 전부 | 알에서 깨어난 뒤에만 |

확인: 안 아픈 상태로 메뉴를 열었을 때 **약만 회색**, 나머지는 정상. (응아 1개가 있어 청소는 켜짐)

## 대사가 빠진 자리가 없는지

말풍선이 비어 보이는 일을 막으려고, **모든 돌보기 × 모든 결과** 조합에 대사가 있는지 시험이 훑는다
(`CareTests.EveryActionAndResultHasSomethingToSay`). 인사·성장·진화 대사도 같이 확인한다.

## 같이 고친 것

- **재운 뒤 영영 자고 있던 문제** — 기운이 다 차면 스스로 깬다. 놀아주면 바로 깬다.
- **청소로 청결도를 무한정 올릴 수 있던 문제** — 치울 응아가 없으면 아예 거절한다.
- `ApplyCare` 가 참/거짓 대신 **이유**를 돌려주게 바꿨다. 그래야 말풍선이 왜 안 되는지 말할 수 있다.
