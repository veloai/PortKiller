# 수첩 실측 기록

> 2026-09-14 / Windows 11 Pro 26200 / .NET 9.0.318

검사 스크립트: `scripts/verify-notebook.ps1`

## 검사 통로를 하나 만들었다

수첩은 트레이 메뉴로만 열린다. 그런데 **윈도우 11 이 새 트레이 아이콘을 숨김 영역에 넣기 때문에
자동 검사가 그 메뉴에 닿지 못한다.**

그래서 앱에 `--open-notebook` 실행 인자를 하나 두었다. 인자를 주면 켜자마자 수첩을 연다.
안 주면 아무 일도 하지 않으므로 일반 사용자에게는 아무 영향이 없다.
"UI 검사 통로가 없으면 만들거나, 검증 미완이라고 명시한다"는 원칙에 따른 것이다.

## 화면 요소는 이름이 아니라 ID 로 찾는다

검사 스크립트는 `추가`, `집중 시작` 같은 **표시 문구로 찾지 않는다.**
WPF 는 `x:Name` 을 AutomationId 로 내보내므로 그걸로 찾는다. 두 가지 이득이 있다.

- 문구를 고쳐도 검사가 안 깨진다
- 스크립트에 한글이 안 들어간다 — Windows PowerShell 5.1 은 `.ps1` 을 MS949 로 읽어서
  한글이 든 스크립트를 통째로 깨뜨린다 (이 저장소에서 이미 한 번 당했다)

## 결과

| 확인 | 방법 | 결과 |
|---|---|---|
| 수첩 창이 뜬다 | UI 자동화로 창 찾기 | 400x560 |

| 잘못된 시각 거절 | `99:99` 로 추가 시도 | 버튼 그대로 7개 + "시각은 14:00 처럼 적어주세요." |
| 뽀모도로 카운트다운 | 시작 후 시계 두 번 읽기 | 25:00 → 24:59 → (3초 뒤) 24:56 |

**전부 통과.**

## 규칙 쪽 시험 (Core)

화면과 별개로 `NotebookTests` 17개가 규칙을 막는다. 특히 아래는 실수하기 쉬운 자리라 못박았다.

- **세 칸을 다 쓰고 다 끝내야 완주다.** 한 칸만 쓰고 체크하는 건 완주가 아니다
- **축하는 완주하는 순간 한 번만.** 체크를 껐다 켤 때마다 파티가 열리면 안 된다
- **날이 바뀌면 할 일이 비워진다.** "오늘 할 일"이므로
- **같은 리마인더가 하루에 두 번 울리지 않는다.** 한 번짜리는 울린 뒤 스스로 꺼진다
- **평일 리마인더는 주말에 조용하다**
- **뽀모도로는 껐다 켜면 복원하지 않는다.** 앱을 껐다 켠 뒤에도 "집중 중"이라고 우기면
  남은 시간이 거짓말이 된다
